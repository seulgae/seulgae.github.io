> 후속 변경: 채용 기능은 PR #91에서 제거됐다. 이 글은 제거 전 설계와 구현을 기록한다. [기능 삭제와 V16 축소](/blog/seulgae-tech-lab-recruitment-removal-schema-contract)에서 이후 과정을 정리했다.

한 공간의 세 담당자가 모두 같은 긴 화면을 보여 주면 사용자는 자기 작업에 필요한 부분을 찾기 어렵다. PR #74·#75는 목록의 양과 업무 책임을 각각 나눴다.

## 다섯 건씩 보여 주되 데이터 경계를 살핀다

공통 페이지 크기는 5다. 이미 받은 배열은 `listPage`로 나누고, 연구 기록이나 회의 안건처럼 서버 조회를 쓰는 화면은 limit과 offset을 전달한다. 화면에서 다섯 건만 보여 주는 것과 서버에서 다섯 건만 요청하는 것은 다르다. 빈 페이지로 이동한 경우 이전 범위로 돌아가는 처리도 있다.

## 역할별로 같은 데이터를 다른 질문에 맞추다

접수 담당은 새 공고와 일괄 접수, 검토 담당은 조건과 근거, 관리 담당은 읽음·확인·지원·보류와 보고를 맡는다. 가까이에서 E키로 담당 화면을 열고 목록에서 선택한 항목을 자세히 본다. 모바일에서는 목록과 상세를 전환한다.

공고를 선택하거나 원문을 열었다는 이유만으로 읽음이나 지원 상태를 자동 변경하지 않는다. 사용자가 명시한 결정만 서버 상태로 남기는 경계다. 개발 문서에는 합성 데이터로 역할별 화면과 모바일 레이아웃을 확인한 기록이 있으며, 운영 데이터 변경이나 운영 반영 테스트는 하지 않았다고 적혀 있다.
