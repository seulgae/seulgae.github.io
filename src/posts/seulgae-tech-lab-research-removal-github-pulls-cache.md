프로젝트의 첫 기능이었던 연구 기록과 아이디어 일지를 정리하고, 개발 연구실 슈퍼컴퓨터에 GitHub PR 목록을 연결했다. PR #86·#89의 로그와 소스를 살펴봤다. 기능을 지울 때는 화면과 API뿐 아니라 운영 스키마, 배포 확인, 다른 기능이 공유하던 코드까지 확인해야 했다.

## 코드를 먼저 떼고 테이블은 나중에 지운다

연구 기록을 사용하지 않는 앱을 먼저 배포하고 V15에서 테이블을 제거하는 축소 순서를 택했다. 중간 릴리스는 V14와 V15를 모두 지원한다. DB를 V15로 옮긴 뒤에는 해당 테이블을 필요로 하는 옛 이미지로 돌아갈 수 없으므로, 배포 호환성 검사가 롤백을 제한한다. 삭제 데이터 복구는 백업에 의존한다.

개발 로그와 PR #89에는 운영 DB에 적용 전 백업을 만든 뒤 V15를 적용하고 릴리스 호환 범위를 15..15로 고정했다고 기록돼 있다. 이번 글 작성에서 운영 DB를 직접 확인하지는 않았다.

## 삭제 대상 안의 공통 의존성을 찾는다

전역 예외 처리기와 여러 화면에서 쓰는 패널 CSS는 연구 기록 기능의 폴더에 있었지만 다른 기능에도 필요했다. 삭제 전에 공통 위치로 옮겼다. 배포 후 확인 역시 기존 연구 기록 API를 호출하고 있어 남아 있는 API로 변경했다. 기능 디렉터리만 지우면 배포 검사가 실패할 수 있는 연결이었다.

## GitHub 호출이 실패하면 마지막 목록을 표시한다

새 PR 목록은 서버에서 공개 API를 호출하고 5분간 캐시한다. 실패 시 마지막 목록을 오래된 결과로 표시하며 1분간 재호출을 미룬다. 처음부터 성공한 결과가 없다면 빈 목록과 오래됨 상태를 돌려준다. 열린 PR과 최근 병합 PR을 구분하지만, 닫힌 PR 조회 결과 일부를 가져와 병합 여부로 거르므로 전체 이력의 완전한 목록이라고 보장하지 않는다.

PR 기록에는 백엔드 109개 통과·5개 건너뜀, 프런트 150개와 빌드 통과가 적혀 있다. 로컬 API에서 실제 목록과 삭제된 API의 404를 확인했지만 게임 화면 스크린샷은 확인하지 못했다.
