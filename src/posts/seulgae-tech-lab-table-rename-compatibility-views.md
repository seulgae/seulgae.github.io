운영 중인 테이블 11개의 이름을 일관된 규칙으로 바꾸려면 데이터뿐 아니라 현재 실행 중인 애플리케이션의 SQL도 고려해야 한다. PR #93·#94는 기존 이름에서 새 이름으로 이동하는 시간을 확보하기 위해 호환 뷰를 사용한다.

## V17에서 옛 이름을 유지한다

V17은 테이블을 `tb_lab_` 접두어를 사용하는 이름으로 변경하고 테이블·컬럼 주석을 추가한다. 예전 이름으로는 새 테이블을 가리키는 단순 뷰를 만든다. 실제 마이그레이션의 한 예다.

```sql
ALTER TABLE lab.members RENAME TO tb_lab_member;
CREATE VIEW lab.members AS SELECT * FROM lab.tb_lab_member;
```

이 구조에서 기존 앱은 예전 이름을 계속 사용할 수 있도록 의도했다. PostgreSQL의 단순 갱신 가능 뷰 조건과 실제 쿼리의 호환성은 별개로 검증해야 한다. PR은 V17을 적용한 PostgreSQL에서 기존 코드의 DB 통합·API 계약 테스트로 읽기와 쓰기를 확인하도록 구성했다. 모든 형태의 뷰나 모든 SQL에 같은 동작을 일반화하지 않는다.

## 새 이름으로 전환하고 호환 뷰를 제거한다

후속 PR #94는 저장소 SQL과 테스트 등을 새 이름으로 바꾸고 V18에서 예전 이름의 뷰를 제거한다. 해당 릴리스는 V17·V18 호환을 의도한다. 데이터 테이블을 지우는 작업이 아니라 뷰를 제거하는 작업이지만, 예전 이름을 쓰는 앱이 아직 있다면 영향을 받으므로 배포 순서가 중요하다.

확인 시점에 #93과 #94는 main에 병합됐다. V17 운영 적용과 #94 배포 및 V18 적용 여부는 이번 확인에서 별도로 검증하지 않았다. PR #94에는 백엔드 102개·1개 건너뜀, 프런트 149개와 타입 검사, 배포 계획 테스트 결과가 기록돼 있다.
