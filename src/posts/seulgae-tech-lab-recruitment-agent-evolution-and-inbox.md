> 후속 변경: 채용 기능은 PR #91에서 제거됐다. 이 글은 제거 전 설계와 구현을 기록한다. [기능 삭제와 V16 축소](/blog/seulgae-tech-lab-recruitment-removal-schema-contract)에서 이후 과정을 정리했다.

서비스 연구실의 채용 담당 NPC는 외부 공고를 검토하는 업무 흐름과 연결됐다. PR #68·#69의 검색 기반 설계와 #70~#72의 접수 중심 변경은 같은 시점의 기능이 아니다. 당시 개발 로그와 채용 문서를 기준으로 변화를 나눠 봤다.

## 처음에는 일정과 규칙을 서버에 두었다

V12는 채용 정보와 작업·출처·이력을 담을 스키마를 준비했다. 초기 기능은 검색 도구를 이용하고 Java 규칙으로 판단하는 구조였다. 일별 작업의 중복을 줄이기 위한 유니크 제약과 DB 락, 선행 작업 검사와 재시도도 설계했다. 확인되지 않은 발췌는 검토 필요 상태로 남겼다.

## 이후에는 정형 공고의 접수로 바뀌었다

V13 기능에서 검색·분석과 서버 접수를 분리했다. 현재 문서에 따르면 외부에서 정형화한 공고를 서버가 받고, 서버가 직접 검색 API나 LLM을 호출하지 않는다. 접수는 한국 날짜 기준 하루 한도와 기업·출처 중복을 확인하며, 배치가 조건에 걸리면 전체를 되돌린다. 기업명 정규화는 서로 다른 별칭을 모두 동일 법인으로 판별해 주지는 않는다.

읽음·확인·지원·보류는 명시적 상태 전이로 남긴다. 지원 기록은 사용자가 직접 지원한 사실을 기록하는 것이며 외부 지원서를 자동 제출하지 않는다. 확인된 마감 이후 원문과 근거를 삭제하는 대신 지원·보류 스냅샷과 최소 원장은 남기는 정책으로 이전 보관 정책을 대체했다. 마감일이 확인되지 않으면 임의 삭제하지 않는다.

문서에는 일회용 PostgreSQL CI에서 중복·한도·상태 순서·마감 삭제 등을 검증하는 계획과 기록이 있다. 이 글을 위해 운영 공고를 등록하거나 삭제하지 않았다. 최초 검색형 구현의 정책을 현재 동작으로 혼동하지 않는 것이 중요하다.
