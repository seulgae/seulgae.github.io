기술 글과 면접 자료에서 확장해 볼 실습을 모았다. 아래 내용은 앞으로 구현·측정할 과제이며 과거 운영 환경의 추가 성과가 아니다. 업무 원본 데이터 대신 생성한 테스트 데이터를 사용한다.

## 1. 순차 조회·병렬 조회·집합 조회 비교

동일한 데이터와 응답 형태를 기준으로 세 구현을 비교한다. 병렬화와 SQL 호출 수 감소는 서로 다른 개선임을 확인한다.

- [ ] 순차 연관 조회, 제한된 동시성의 병렬 조회, 집합 조회 방식을 구현한다.
- [ ] 반환 데이터와 정렬이 동일한지 확인한다.
- [ ] 데이터 규모·동시 요청·DB 연결 수를 고정하고 SQL 수·응답 시간·실패율·DB 부하를 기록한다.
- [ ] 병렬 요청 증가 시 연결 대기·시간 초과를 재현하고 적용 한계를 정리한다.

제출물: 실행계획·SQL 수와 p50/p95/p99 비교표, 병렬화가 유리하거나 불리한 조건.

## 2. Kafka 매핑·중복 이벤트·대사 복구

- [ ] 원천·응용 키와 컬럼이 다른 이벤트를 만들고 매핑 조회·DTO 변환을 구현한다.
- [ ] 동일 이벤트 재전달, 매핑 누락, 대상 저장 실패를 각각 주입한다.
- [ ] 이벤트 처리·DB 반영·커밋 경계를 명시하고 중복 반영 방지와 재처리 방식을 선택한다.
- [ ] 원천·대상 비교로 누락·불일치를 찾고 보정 전후 결과를 확인한다.

제출물: 정상·실패 흐름도, 중복·누락 재현 절차, 재처리 뒤 정합성 확인 결과. 새로 선택한 DLQ·멱등 처리 등을 과거 경험에 덧붙이지 않는다.

## 3. Jsoup HTML 필터와 출력 문맥

- [ ] 일반 텍스트 출력 인코딩과 에디터 HTML 필터링을 분리해 구현한다.
- [ ] 필요한 태그·속성·링크 프로토콜을 정하고 테스트용 입력을 작성한다.
- [ ] 스크립트 태그, 이벤트 속성, 위험한 URL, 잘못 닫힌 태그를 넣어 결과를 확인한다.
- [ ] 허용한 서식·이미지·링크가 유지되는지와 브라우저 실행 결과를 함께 확인한다.
- [ ] 예외 메시지·로그·콜백·빈 문자열의 입력 계약도 별도 테스트로 점검한다.

제출물: 필터 정책과 입력·변환 결과 표, 브라우저 확인 결과. 과거에 사용한 정책을 그대로 복원했다는 주장은 하지 않는다.

## 4. 엑셀 다운로드의 전체 메모리 흐름

- [ ] XSSF와 SXSSF를 같은 데이터·제한된 힙 환경에서 비교한다.
- [ ] DB 조회 목록·Workbook·응답 버퍼·임시 파일의 사용량을 구분한다.
- [ ] 동시 다운로드·클라이언트 중단·파일 생성 실패 시 자원 정리를 검증한다.
- [ ] 사용한 POI 버전과 close·임시 파일 정리 동작을 기록한다.

제출물: 건수·힙 제한·동시 요청별 메모리와 시간 비교, 실패 후 남은 파일·자원 확인.
