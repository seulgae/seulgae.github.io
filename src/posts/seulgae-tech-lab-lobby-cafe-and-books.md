로비를 지나가는 통로에서 잠깐 머무는 공간으로 바꾸고 싶었다. PR #31의 `dcbf97a`에서는 안내 데스크의 커피와 케이크, 책장의 기술 노트를 상호작용 대상으로 만들었다. 당시에는 동전이나 HP가 연결되지 않은 브라우저 전용 연출이었다.

## 가벼운 기록에 서버 저장이 필요할까

커피를 몇 잔 마셨는지는 이 브라우저에서 오늘의 분위기를 만드는 값이었다. 다른 방문자와 합의할 필요가 없어 localStorage에 날짜와 횟수만 저장했다. 로그인 사용자별 기록이나 서버의 재화 장부로 취급하지 않았다.

현재 `frontend/src/game/rooms/roomEventLogic.ts`는 브라우저의 날짜를 명시적으로 만든다.

```ts
export function localDay(date: Date) {
  const pad = (value: number) => String(value).padStart(2, '0')
  return `${date.getFullYear()}-${pad(date.getMonth() + 1)}-${pad(date.getDate())}`
}
```

UTC 날짜를 잘라 쓰면 현지 자정과 횟수 초기화 시점이 어긋날 수 있다. 저장 JSON이 깨졌거나 날짜가 다르거나 횟수가 유효하지 않으면 새 기록으로 시작한다. 저장 실패가 게임 전체를 멈추게 하지 않는 것도 이 값의 성격에 맞는 선택이다.

같은 파일의 메시지 분기다.

```ts
  if (kind === 'coffee') {
    if (count === 1) return '오늘 첫 커피! 집중력이 올라가요'
    return count >= 4 ? `오늘 커피 ${count}잔째 · 물도 한 잔 마셔요` : `오늘 커피 ${count}잔째`
  }
```

이 문구는 당시 게임 연출이다. 실제 능력치 상승을 구현했다는 의미로 읽으면 안 된다. 이후 간식 가격과 회복 기능이 들어간 현재 동작은 별도 글에서 다룬다.

## 책이 도착한 뒤에 읽기 창을 열기

책장은 E 입력을 받으면 책 한 권이 캐릭터 쪽으로 날아오고, 그 뒤 React 창이 열리게 했다. RoomFx는 연출을 시작한 뒤 기본 패널 경로가 이어지도록 처리하고 Scene은 450ms 뒤 읽기 창을 연다. 애니메이션과 패널 열기를 동시에 실행하면 책이 날아오는 과정을 창이 가려 버린다.

기술 노트는 정적 데이터로 분리했다. `frontend/src/features/books/BookPanel.tsx`의 페이지 이동은 범위를 제한한다.

```ts
  const open = (index: number) => { setBookIndex(index); setPage(0) }
  const turn = (delta: number) => setPage(value => Math.min(Math.max(value + delta, 0), book.pages.length - 1))
```

책을 바꾸면 첫 쪽으로 돌아가고 좌우 키와 버튼이 같은 함수를 사용한다. 책등 색상과 본문 데이터가 나뉘므로 화면 로직에 글 내용을 섞지 않아도 된다.

## 가장 가까운 물체가 항상 의도한 대상은 아니다

책장 옆 식물에 다가갔는데 책장이 선택되는 문제가 있었다. 가장자리 거리만 비교하면 조금 더 가까운 큰 책장이 이길 수 있었다. `rooms.ts`는 책장을 아래쪽 절반에서 접근할 때만 후보에 넣는다. 거리 계산 전에 사용자가 실제로 접근하는 면을 반영한 것이다.

자주 지나치는 의자 안내도 짧게 줄였고, 자동 회의 모드 전환은 배너 없이 조명으로 알렸다. 안내가 많다고 사용성이 좋아지는 것은 아니었다.

로그에는 소품 화면 확인과 Scene 하네스의 E 처리 검증이 남아 있다. 숨겨진 브라우저에서는 프레임 갱신이 멈춰 실제 E 조작 전체를 확인하지 못했다. 이번 작성에서도 운영 상호작용은 **확인하지 못함**이다.

## 배운 점

로컬 분위기와 공유 재화는 저장 책임부터 구별해야 했다.
연출과 패널을 순서대로 연결해야 짧은 동작도 눈에 들어왔다.
대상 선택에는 거리 외에 접근 방향이라는 조건이 필요했다.
