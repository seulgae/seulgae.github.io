포트폴리오의 서비스 목적·담당 범위·기술 버전 표기와 검수 문구 분리는 반영했다. 완료한 수정 목록과 이전 문구 비교는 이 글에서 제외하고, 저자의 실제 경험으로 확인할 항목만 남겼다.

저장소에서 확인하지 못했다는 이유만으로 미구현이라고 판단하지 않는다. 한 항목씩 저자와 확인한 뒤 필요한 내용은 해당 기술 글에 반영하고, 해결한 질문은 이 목록에서 제거한다.

## 1. 권한 조회 캐시 — 사이드 프로젝트 검증으로 전환

기억이 불분명한 만료·무효화·장애 설정은 과거 실적으로 채우지 않는다. 저자와 확인한 로그인·재로그인 시 권한 API 조회·Redis 저장 및 갱신, 이후 요청에서 캐시 재사용, TTL을 통한 보관 기간 제한은 원문에 남긴다. 약12시간은 기억 수준이다.

남은 동작은 [Redis 권한 캐시 사이드 프로젝트 설계](/blog/redis-permission-cache-side-project)로 옮겼다. 구현과 측정은 아직 수행하지 않았으며, 이 항목은 과거 요구사항의 누락이나 실무 개선 미완료 과제로 취급하지 않는다.

## 2. 성능·오류 수치의 측정 조건

- Kafka 오류는 메시지 저장 내역·GW 모니터링을 근거로 보고용 엑셀에서 정리·비교했다. 비교한 주수·중복 오류 포함 기준·처리량 조건까지 확인된 것은 아니다.

병렬 조회의 최종 수치 **약 480,000ms → 10,000ms 이내**는 이미 저자가 확인했다. 수치를 다시 의심하는 질문이 아니라 대상·측정 조건을 설명하기 위한 확인이다. 당시 성과가 병렬화이며 SQL 호출 수 감소가 아니라는 구분은 유지한다.

## 3. 망간 동기화·보안 조치

- 에디터 HTML 처리는 [CWE-79 조치 기록](/blog/cwe-79-xss-remediation)을 참조한다. 원문에서 확인되는 조치는 입력 필터·에디터 정책과 raw 출력 통로 정리다. 서버 HTML 정화 구현은 원문에도 확인 필요로 남아 있어 완료로 판정하지 않는다.
