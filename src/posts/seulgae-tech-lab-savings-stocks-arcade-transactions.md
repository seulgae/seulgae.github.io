게임 속 동전을 적금과 가상 주식, 오락실 게임에서도 쓰려면 잔액 변경과 결과를 일관되게 다뤄야 한다. 개발 로그 71·72번과 PR #104·#105를 살펴봤다. **확인 시점에 V20 확장 PR #104는 병합됐고 기능 PR #105는 열려 있다.** 운영에서 기능이 동작한다고 단정하지 않는다.

## 스키마 확장과 기능 사용의 순서

V20은 적금, 종목·시세 이력·회원 보유 수량과 동전 장부 사유를 준비한다. 확장 릴리스는 V19와 V20을 지원하고, 기능 릴리스는 V20을 요구하도록 나눴다. PR 계획은 확장 릴리스 배포와 운영 마이그레이션을 확인한 뒤 기능을 병합하는 순서다.

## 적금은 성공한 요청만 지급한다

적금은 가입 시 기간과 이율을 정하고, 만기에는 이자를 더하며 중도 해지에는 원금을 돌려준다. 찾기 요청은 아직 닫히지 않은 행만 닫도록 조건부 갱신한다. 그 갱신에 성공한 요청만 잔액을 지급해 같은 적금을 두 번 수령하는 경쟁을 막는다. 시간은 주입 가능한 시계를 통해 테스트한다.

## 가상 시세는 조회할 때 따라잡는다

시세 갱신은 별도 스케줄러 대신 조회 시 마지막 갱신부터 지난 10분 단위만큼 계산한다. 한 번에 따라잡는 횟수에는 상한이 있다. 읽었던 갱신 시각을 조건으로 업데이트해 동시에 여러 요청이 같은 시세를 갱신할 때 한 요청이 반영하고 나머지는 다시 읽는다. 운영 환경에서의 동시성 효과는 실제 DB 검증 범위로 판단해야 한다.

오락실 네 게임의 결과는 서버가 난수로 결정하고 화면은 그 결과를 연출한다. 문서에 기록된 확률·이율은 **게임 안의 가상 규칙**이다. 결과와 장부가 연결되는 방식은 실제 금융 상품의 수익률이나 투자 설명이 아니다.

## 확인한 범위

PR과 개발 로그에는 백엔드 테스트 118개·1개 건너뜀, 프런트 테스트 154개와 타입 검사 결과가 기록돼 있다. 화면은 로그인과 API 응답을 대체해 확인했으며 실제 서버 응답은 당시 확인하지 못했다. 이 글을 위해 프로젝트 테스트나 운영 거래를 다시 실행하지 않았다.
