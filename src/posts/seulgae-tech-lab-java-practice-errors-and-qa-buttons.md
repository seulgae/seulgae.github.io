내 자리 컴퓨터의 Java 연습에서 형식 문자열을 실행하면 계속 실패 메시지가 보였다. QA 게시판에서는 상태를 바꾸는 버튼이 글자처럼 보여 조작할 수 있다는 사실을 알아보기 어려웠다. PR #112·#113과 개발 로그를 통해 두 문제를 살펴봤다.

## 반복 실행에 글쓰기 제한을 그대로 적용한 문제

Java 연습은 입력을 고쳐 여러 번 실행하는 흐름인데 게시판 글쓰기와 같은 제한이 적용돼 있었다. 연속 요청이 제한되면 서버는 429를 반환했지만 화면은 이를 구분하지 않고 실행 실패로 표시했다. 사용자는 답이 틀린 것인지, 요청이 제한된 것인지 알기 어려웠다.

수정에서는 Java 연습에 글쓰기 제한 대신 회원당 1초 간격의 요청 제한을 적용했다. 정답 보상의 일일 한도는 별도로 유지한다. 화면에서는 429, 로그인 만료와 입력 길이 오류를 구분해 안내한다. 요청 제한을 완화하는 일과 보상 한도를 없애는 일은 다른 판단이다.

또 다른 혼란은 입력 범위였다. `%s`만 넣으면 그 자리에 들어갈 값만 출력된다. 기대 결과가 인사 문장 전체라면 형식 문자열에도 문장 전체를 써야 한다. 개발 창에 이 차이를 예시와 함께 설명하도록 보완했다.

## 목록 버튼 스타일이 단계 버튼까지 덮었다

QA 티켓 목록의 버튼을 투명 배경·전체 너비로 표시하는 CSS가 펼쳐진 티켓의 단계 변경 버튼에도 적용됐다. #113에서는 작업 버튼에 더 구체적인 스타일을 적용해 배경과 테두리, 정렬을 구분했다. 같은 `button` 요소라도 목록 선택과 상태 변경은 역할이 다르기 때문에 시각적 신호도 달라야 했다.

## 확인한 범위

#112 PR에는 백엔드 테스트, 프런트 테스트 161개와 타입 검사 통과가 기록돼 있다. 개발 로그에는 프런트 160개로 적혀 있어 수치는 기록별 차이가 있다. 운영에서 반복 실행하는 확인은 당시 남은 과제였다. #113은 로컬 브라우저에서 버튼 모양을 확인했다고 기록했다. 이 글을 작성하면서 두 기능을 운영에서 재검증하지 않았다.
