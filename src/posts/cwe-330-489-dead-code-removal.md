시큐어코딩 점검에서 흥미로운 통계가 하나 나왔다. **CWE-330(부적절한 난수),
CWE-489(활성 디버그 코드), CWE-497(시스템 정보 노출)** 검출을 추적해 보니,
대부분이 실서비스 코드가 아니라 **아무도 쓰지 않는 코드**에서 나온 것이다.

## 발견된 것들

- **벤더 인증 모듈 잔재** — 과거에 쓰다 중단한 인증서 로그인 모듈이 통째로 남아
  있었다. 그 안의 `Math.random()` 기반 세션 ID 생성, 난독화 번들 속 취약 난수가
  CWE-330으로 줄줄이 검출됐다.
- **진단/샘플 페이지** — 서버의 시스템 프로퍼티 전체를 화면에 덤프하는 벤더 진단용
  JSP(CWE-497), 본인확인 연동 샘플, 컴포넌트 테스트 화면(CWE-489).
- **테스트 컨트롤러** — 개발 중 연계 테스트용으로 만든 컨트롤러가 배포 대상에
  포함되어 있었다.
- **미사용 연동 기능** — 쿠키 값으로 사용자를 식별하는 소셜 로그인 연동 코드
  (CWE-807, 신뢰할 수 없는 입력 기반 보안 결정). 화면 진입점도, 인터셉터 등록도
  없는 죽은 기능이었다.

## 조치 — 고치지 않고 지우기 위한 확인 절차

이런 코드는 escape를 씌우고 난수를 SecureRandom으로 바꾸는 "수리"가 답이 아니다.
**쓰지 않음을 증명하고 지우는 것**이 답이다. 다만 증명 없이 지우면 사고가 나므로,
파일마다 같은 절차를 밟았다.

1. **진입점 역추적** — 컨트롤러 매핑, 화면 흐름, include/script 로드 관계를 따라
   이 파일에 도달하는 경로가 있는지 확인
2. **참조 전수검색** — 활성 화면에서의 참조가 0건인지 소스 전체 검색으로 확인
3. **실사용 대체재 확인** — 예를 들어 실서비스 인증코드 생성은 `SecureRandom`을
   쓰고 있음을 확인해서, 삭제 대상이 실기능과 무관함을 기록
4. **삭제 + 사유 기록** — 조치 내역에 "미사용 근거"를 남겨 감리에 대응

이 절차로 벤더 모듈 디렉터리, 테스트 화면, 테스트 컨트롤러, 미사용 연동 기능을
삭제해 수십 건을 종결했다. 파일 하나 지우면 그 안의 검출 여러 건이 함께 사라지므로,
건수 대비 효율이 가장 높은 조치이기도 했다.

## 덤 — 미사용 유틸의 TOCTOU (CWE-367)

파일 목록을 나열한 뒤 각 파일의 상태를 읽는 사이에 파일이 바뀔 수 있다는
경쟁조건 검출도 있었다. 확인해 보니 어디서도 인스턴스화되지 않는 파일 감시 유틸.
같은 원칙(미사용 확인 → 해당 구간 제거)으로 정리했다.

## 배운 점

- 취약점의 상당수는 "잘못 짠 코드"가 아니라 **"지웠어야 할 코드"** 에서 나온다.
  벤더 샘플, 테스트 화면, 중단된 연동 — 배포 산출물에 실리는 순간 전부 공격 표면이다.
- 삭제는 가장 강력한 보안 조치지만, 근거 없는 삭제는 장애의 지름길이다.
  "진입점 역추적 → 참조 검색 → 사유 기록"의 절차화가 삭제를 안전한 조치로 만들었다.
