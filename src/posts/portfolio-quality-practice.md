현재 포트폴리오의 남은 품질 개선을 직접 구현하고 검증하는 과제다. 각 항목은 체크를 완료하기 전까지 구현 결과로 취급하지 않는다. 기존 콘텐츠·라우터·Markdown 처리 방식을 활용한다.

## 1. 모달 키보드 접근성

아키텍처 모달은 초기 초점과 Escape 닫기를 제공하지만, 배경으로 초점이 빠지는 상황을 보완할 여지가 있다.

- [ ] 열기 버튼에 초점을 둔 상태에서 모달을 열고 Tab·Shift+Tab 이동을 재현한다.
- [ ] 모달 안에서 초점이 순환하고 배경 요소는 조작되지 않도록 개선한다.
- [ ] 닫으면 열기 버튼으로 초점이 돌아오도록 한다.
- [ ] 내부 확대 dialog와 Escape가 충돌하지 않는지 확인한다.

제출물: 변경 전후 키보드 조작 기록, 모달 열기·닫기·초점 복귀 검증 결과.

## 2. 공개 파일과 개인정보

연락처 텍스트와 증빙 이미지의 공개 범위는 따로 살펴본다. public 파일은 화면에 링크가 없어도 빌드에 포함될 수 있으므로 배포 산출물도 확인한다.

- [ ] 자격·교육·수상 이미지에서 공개가 필요한 정보와 가릴 정보를 구분한다.
- [ ] 공개용 마스킹 사본을 준비하고 이미지에 남은 식별 정보가 없는지 확인한다.
- [ ] 원본 보관 위치와 Git 추적 이력을 점검한다. 사이트 파일 교체가 과거 이력까지 지우지는 않는다는 점을 구분한다.
- [ ] 환경 파일 제외 규칙을 검토하고 이미 추적 중인 파일도 별도로 확인한다.

제출물: 민감한 실제 값을 재기재하지 않은 점검표와 공개용 이미지 변경 내역. 원본 삭제나 이력 재작성은 별도 범위 확인 후 진행한다.

## 3. GitHub Pages 경로와 공유 미리보기

현재 직접 주소 접근은 404 페이지에서 경로를 보관하고 루트로 이동해 복원하는 구조다. 브라우저에서 본문을 읽는 것과 최초 HTTP 응답·공유 수집기의 결과를 나눠 검증한다.

- [ ] 홈·블로그 목록·상세 글·이력서의 직접 접근과 새로고침을 배포 환경에서 기록한다.
- [ ] 현재 사이트에 맞는 공유 이미지를 준비하고 OG·Twitter 메타를 확인한다.
- [ ] 글별 메타·canonical·사이트맵과 정적 HTML 생성의 필요성을 비교한다.
- [ ] 기존 글 주소와 검색·본문 렌더링을 유지하는 범위에서 적용안을 선택한다.

제출물: 주소별 최초 상태·최종 표시 결과 표, 공유 카드 확인 결과와 선택한 배포 방식의 이유.

## 4. 리소스·의존성과 로딩

- [ ] 초기 로딩 파일과 전체 배포 폴더 용량을 나눠 측정한다.
- [ ] public 이미지·SVG의 참조를 확인하고 화면용 축소본·최적화본을 비교한다.
- [ ] 동적 클래스·반응형·인쇄 스타일을 확인한 뒤 미사용 CSS 후보를 분류한다.
- [ ] 의존성 공지의 적용 조건과 실행 위치를 확인하고 호환 업데이트 후 회귀 검증한다.
- [ ] Markdown 로딩 방식을 바꾼다면 본문 검색과 글 목록 기능이 유지되는지 비교한다.

제출물: 변경 전후 요청 수·전송량·빌드 크기와 재현 조건. 실제 측정 없이 로딩 속도 개선율을 만들지 않는다. 참고 주석·src/old·파일 삭제는 별도 승인 범위다.

## 5. 반응형·인쇄 최종 확인

- [ ] 모바일·태블릿·데스크톱에서 본문과 구성도 가로 넘침을 확인한다.
- [ ] 작은 글씨·날짜·버튼의 색상 대비와 키보드 초점 표시를 확인한다.
- [ ] 실제 A4 인쇄 미리보기에서 페이지 수·잘림·링크 표현을 확인한다.
- [ ] 기존 테스트와 빌드, 내부 글 링크·이미지 경로 검사를 수행한다.
