이전에 만들었던 채용 접수·검토 기능은 이후 제거됐다. PR #91·#92와 개발 로그를 기준으로, 기존 글에서 설명한 채용 화면이 현재 기능으로 오해되지 않도록 삭제 과정을 따로 정리한다.

## API를 먼저 제거하고 DB를 축소한다

채용 서버 패키지와 화면·도구를 제거한 앱은 V15와 V16을 모두 지원하도록 준비했다. 이어서 V16에서 채용 테이블 11개를 외래 키 관계의 자식부터 삭제했다. 먼저 백업하고 테이블을 더 이상 사용하지 않는 앱을 배포한 뒤 마이그레이션하는 순서다. `DROP TABLE`은 데이터를 지우므로 이전 앱으로의 복귀 가능 범위도 함께 확인해야 한다.

PR #92와 개발 로그에는 운영에서 백업 후 V16을 적용하고 릴리스 범위를 16..16으로 좁혔다고 기록돼 있다. 이전에 작성한 채용 설계 글은 당시 구현의 기록이며, 지금도 해당 기능이 존재한다는 뜻이 아니다.

## 남은 공간의 역할을 다시 정한다

채용 담당 NPC 세 명은 일반 작업석 연구원으로 바뀌었다. 일정 간격으로 한 명씩 대사와 표정 연출을 보여 주고, 말을 걸면 짧게 답한다. 채용 화면이나 담당자 이름표와 연결하지 않는다. 기존 공간과 애니메이션을 남기되 삭제한 서버 기능에 의존하지 않게 했다.

## 테스트가 작업 트리를 변경한 경험

개발 로그에는 배포 도구 테스트가 실제 배포 경로를 호출하면서 로컬 저장소를 릴리스 커밋으로 체크아웃한 사고가 기록돼 있다. 변경 사항이 stash에 남아 있음을 확인하고 원래 브랜치와 변경을 복구했다. 테스트 이름만으로 안전하다고 생각하지 않고, 실제 Git 명령이나 외부 상태 변경이 있는지 확인해야 했던 사례다. 당시 로컬에서는 해당 테스트를 제외하고 CI에서 확인하기로 했다.

PR에는 백엔드 102개·1개 건너뜀, 프런트 149개와 타입 검사·빌드, 배포 계획 테스트 통과가 기록돼 있다. 이번 글 작성에서 그 테스트를 재실행한 것은 아니다.
