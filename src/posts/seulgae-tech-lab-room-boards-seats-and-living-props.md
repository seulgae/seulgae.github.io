슬개기술연구소는 중앙 로비와 개발 연구실, 서버실, 회의실을 오갈 수 있는 공간으로 확장됐다. 다음으로는 공간을 구경하는 데서 그치지 않고, 방문자가 짧은 기록을 남기고 의자에 앉아 대화할 수 있도록 기능을 더했다.

이번 글은 [커밋 55fe053](https://github.com/seulgae/seulgae-tech-lab/commit/55fe053a2b79bbfc18f85bcd9b4631113ed98389)과 해당 커밋에 포함된 [작업 문서](https://github.com/seulgae/seulgae-tech-lab/blob/55fe053a2b79bbfc18f85bcd9b4631113ed98389/docs/room-boards-and-props.md)를 기준으로 정리한 개발 기록이다. 커밋 메시지와 설명만 옮기지 않고, 수정 키 구현과 Flyway V2 SQL, 프런트엔드 테스트도 함께 확인했다. 이 글을 작성하면서 테스트를 다시 실행하거나 운영 서버를 검증하지는 않았다.

## 회의실에는 안건을, 로비에는 짧은 일지를 남기기

회의실 화이트보드에서 E를 누르면 안건 패널이 열리도록 구성했다. 안건은 목록 조회와 작성, 작성한 브라우저에서의 수정·삭제를 지원한다. 제목은 칠판에 짧게 표시할 수 있도록 8자, 내용은 130자로 제한했다.

화이트보드에는 최근 안건 다섯 개의 제목이 6초 간격으로 돌아가며 표시된다. 목록은 20초마다 다시 조회하고, 같은 브라우저에서 내용을 변경하면 갱신한다. 이 주기와 동작은 작업 문서에 기록된 구현 기준이다.

로비에는 연구 기록 패널을 이용한 아이디어 일지를 추가했다. 기본 제목은 `연구 아이디어 일지 #N`이며, 사용자가 제목을 수정할 수 있다. 제목은 40자, 내용은 130자까지다. 번호는 기존 제목 중 해당 형식의 가장 큰 번호에 1을 더해 안내한다. **이 번호를 동시 작성에서도 유일한 식별자를 보장하는 기능으로 설명하지는 않는다.**

| 기능 | 저장 대상 | 주요 API |
| --- | --- | --- |
| 회의 안건 | `lab.meeting_agendas` | `/api/meeting-agendas` |
| 연구 아이디어 일지 | 기존 연구 기록 테이블 | `/api/research-records/ideas` |

기존 개발 전용 일반 작성 API를 운영에서 모두 여는 대신, 이번 기능을 위한 별도 작성 경로를 추가했다.

## 로그인 없이 수정 권한을 어떻게 구분했나

로그인을 추가하지 않았기 때문에 사용자 계정으로 작성자를 식별할 수 없다. 이번 구현은 **글을 작성한 브라우저가 보관하는 수정 키**로 편집 권한을 확인한다.

```text
글 작성
  → 서버가 32바이트 임의 수정 키 생성
  → DB에는 키의 SHA-256 해시 저장
  → 생성 응답에서 원문 키를 한 번 반환
  → 브라우저가 localStorage에 보관
  → 수정·삭제 요청의 X-Edit-Token 헤더로 전달
```

`EditTokens` 코드에서는 `SecureRandom`으로 키를 만들고 URL-safe Base64로 표현한다. 저장된 해시와 요청 키의 해시는 `MessageDigest.isEqual`로 비교한다. 형식이 맞지 않거나 기존 해시가 없는 경우에는 거부한다.

이 방식은 계정 인증을 구현한 것이 아니다. 키를 가진 쪽이 편집 권한을 갖는다. 브라우저 저장소를 지우거나 다른 기기에서 접속하면 기존 글을 편집할 수 없으며, 키가 노출되면 그 권한도 노출된다. 로그인·권한 복구·관리자 화면은 이번 구현에 포함되지 않는다.

요청 본문의 길이와 제어 문자도 검사하고, 작성·수정·삭제에는 주소별 제한과 서버 전체 제한을 함께 둔다. 작업 문서에는 주소별 여유 5회와 12초당 1회 보충, 전체 여유 30회와 30초당 1회 보충으로 기록돼 있다. 주소 판정에 쓰는 전달 헤더만으로 신뢰할 수 있는 사용자를 식별한다고 보지는 않는다.

## V1 데이터를 지우지 않고 Flyway V2로 확장하기

이번 커밋의 V2 SQL에는 두 가지 변경이 있다.

- 기존 연구 기록에 `edit_token_hash`, `updated_at` 컬럼 추가
- 회의 안건을 저장하는 `lab.meeting_agendas` 테이블과 목록 조회용 인덱스 추가

회의 안건의 제목 8자·내용 130자 제한은 DB 제약에도 반영했다. 기존 V1 연구 기록에는 수정 키 해시가 없으므로 새 편집 경로로 수정·삭제할 수 없도록 구분했다.

배포 관련 코드도 함께 달라졌다. 작업 기록 기준으로 사전 점검은 V1/V2를 확인하도록 확장됐고, 명시적 마이그레이션 도구는 백업을 포함한 V2 전환을 지원한다. CI의 새 릴리스는 스키마 호환 범위를 `2..2`로 선언한다.

**코드에 V2 마이그레이션이 있다는 사실과 운영 DB에 V2가 적용됐다는 사실은 별개다.** 이 글에서는 운영 적용 완료를 확인하지 않았다. 과거 단계의 “V1만 필요하다”는 안내를 새 릴리스에 그대로 적용하거나, 운영 마이그레이션을 이미 수행한 것처럼 서술하지 않는다.

## 의자에 앉는 모습과 실제 충돌 위치를 분리하기

의자는 공유 맵의 `chair` 가구를 기준으로 방별 ID를 만든다. 클라이언트와 서버가 같은 규칙으로 의자를 찾는다.

```json
{"type":"seat","seatId":"lobby-chair-0","roomEpoch":1}
```

서버는 같은 방인지, 의자와의 거리가 40px 이내인지, 자리가 비어 있는지 확인한다. 앉은 상태는 플레이어의 `seat` 값으로 다른 방문자에게 전달한다. 이동 명령이 처리되거나 방을 바꾸면 자리도 비운다.

클라이언트는 서버 응답을 기다리는 동안 먼저 앉은 모습을 표시한다. 1.5초 안에 서버 확인이 없으면 일어난다. 캐릭터 외형은 의자 위에 표시하지만, 서버 좌표와 물리 몸체는 의자 뒤에 유지한다. 앉은 연출 때문에 기존 충돌 좌표까지 임의로 옮기지 않으려는 구성이다.

회의실에서는 의자에 앉으면 테이블 대화가 켜지고, 일어나면 꺼진다. 앉은 위치도 대화에 참여할 수 있도록 테이블 대화 범위는 64px에서 96px로 넓혔다. 채팅 자체는 기존 WebSocket 경로를 사용하며 Kafka를 새 전달 경로로 추가하지 않았다.

## 식물과 창문, 시계는 브라우저 안의 연출로 만들기

모든 변화를 서버에 동기화할 필요는 없었다. 식물을 클릭하거나 가까이에서 E를 누르면 화분이 흔들리고 나뭇잎 아홉 장이 떨어지도록 했다. 이 효과는 각 브라우저에서만 보이며, 흔들리는 동안에는 다시 시작하지 않는다.

창문은 브라우저의 현재 시각을 기준으로 새벽·이른 아침·아침·점심·노을·저녁의 여섯 시간대를 표현한다. 하늘은 1분마다 갱신하고, 창으로 들어오는 빛과 실내등의 분위기도 바꾼다. 벽시계는 1초마다 시·분·초침과 `HH:MM` 표시를 갱신한다.

이는 방문자의 로컬 시각에 따른 표현이다. 서로 다른 시간대의 방문자에게 동일한 서버 시간을 보여 주는 기능으로 설명하지 않는다. 의자처럼 다른 사람에게 영향을 주는 상태와 식물·하늘처럼 개별 화면의 분위기를 만드는 효과를 구분했다.

## 검증된 기록과 남은 확인 사항

작업 문서에는 다음 검증 항목이 기록돼 있다.

| 영역 | 기록된 검증 범위 |
| --- | --- |
| 입력·수정 키 | 글자 수, 제어 문자, 수정 키, 주소별·전체 제한 |
| 게시판 서비스 | 해시 저장, 수정·삭제 권한, 403·404, 길이 제한, V1 기록 보호 |
| 의자 | 의자 목록, 거리, 빈자리, 이동 시 일어남 |
| 프런트엔드 | 게시판 API·수정 키 처리, 상호작용과 시간대 연출 관련 테스트 |

이 표는 **저장소에 남은 검증 기록의 요약**이다. 이번 글 작성에서 해당 테스트를 다시 실행해 얻은 결과가 아니므로 새 테스트 수나 CI 성공 여부를 덧붙이지 않았다.

로컬 확인 기록에는 DB 없는 메모리 백엔드에서 안건 작성 201, 9자 제목 거부 400, 일지 작성과 다음 번호 조회를 확인한 내용이 있다. 이는 운영 PostgreSQL에 데이터를 저장해 검증했다는 뜻은 아니다. 브라우저 기록에는 시간대가 반영된 창밖과 벽시계 표시도 포함돼 있다. 반면 숨겨진 브라우저에서 게임 루프가 멈춰 E로 패널을 여는 전체 흐름, 앉은 모습, 식물 흔들림은 확인하지 못했다고 명시돼 있다. 구현된 기능과 실제로 눈으로 확인한 기능을 같은 수준의 검증으로 취급하지 않았다.

## 공간을 늘린 뒤에는 상태의 책임도 나눠야 했다

방 이동 다음 단계에서 추가한 것은 장식만이 아니었다. 게시글은 DB와 수정 권한이 필요했고, 의자는 서버의 거리·점유 검증이 필요했다. 식물과 시간대 연출은 각 브라우저에서 처리했다.

짧은 기록 하나에도 입력 제한, 편집 권한, 기존 데이터 보호, 스키마 호환성이 따라왔다. 이번 변경은 연구소를 더 살아 있는 공간으로 만드는 과정이면서, **서버가 검증할 상태와 화면에서만 표현할 효과를 구분하는 작업**이었다.
