> 일상을 기록하고, 지식을 축적하며, 성장을 설계하는 공간.

취업을 준비하면서 생활비는 Google 스프레드시트에 기록하고, 채용공고는 AI로 분석한다. 일정과 일일 체크리스트를 관리하고, 기술 학습과 면접 준비를 진행하며, 블로그에는 경험과 배운 내용을 정리한다.

각 도구는 저마다 역할이 있지만, 여러 곳에 쌓인 기록을 다시 찾아 연결하려면 도구 사이를 오가야 한다. 지출 내역을 보면서 남은 생활비를 확인하고, 채용공고를 살펴보면서 준비할 기술과 일정을 함께 관리할 수 있다면 어떨까.

이 질문에서 개인 사이드 프로젝트 **슬개리움(Seulgaerium)**을 시작하게 됐다. 슬개 기술연구소(Seulgae Tech Lab)에서 진행하는 AI 기반 개인 통합 관리 플랫폼이다. 내가 실제 일상에서 사용하면서 필요한 기능을 발견하고, 취업 이후에도 계속 운영하며 발전시키는 것을 목표로 한다.

## 슬개리움이라는 이름

슬개리움은 **슬개(Seulgae)**와 특정 목적을 위한 공간을 나타내는 라틴어 유래 접미 요소 **-arium**에서 착안해 만든 이름이다. 일상과 지식, 경험이 쌓이고 그 기록을 바탕으로 다음 목표를 세우는 디지털 공간을 뜻한다.

슬로건에 담은 ‘기록’, ‘축적’, ‘성장’은 서비스의 방향이기도 하다. 오늘 지출한 금액과 완료한 일정, 학습한 내용을 남기고, 시간이 지난 뒤에도 그 기록을 다시 활용할 수 있는 구조를 만들고 싶다.

## 실제로 사용할 문제에서 출발하기

프로젝트의 출발점은 새로운 기술을 적용할 기능을 찾는 일이 아니라, 이미 반복하고 있는 활동에서 불편을 발견하는 일이다.

| 현재 관리하는 활동 | 슬개리움에서 다루고 싶은 방향 |
| --- | --- |
| 스프레드시트의 지출 내역 | 데이터를 연동해 분류별 소비와 월별 예산을 확인 |
| 채용공고 분석과 지원 준비 | 공고와 분석 결과, 전형 진행 현황을 연결 |
| 일정과 일일 체크리스트 | 계획과 완료 상태, 실행 결과를 함께 관리 |
| 기술 학습과 면접 준비 | 검증한 문제와 답변 이력을 바탕으로 복습 |
| 블로그 기록 | 개발 과정에서 얻은 판단 근거와 경험을 정리 |

기존에 사용하던 도구의 데이터를 어떻게 가져오고 어떤 기능부터 직접 관리할지는 요구사항 분석에서 결정할 예정이다. 생활에 필요한 범위를 먼저 정하고, 실제 사용하면서 개선할 수 있는 서비스를 만들고자 한다.

## 구상 중인 서비스

### 사용자와 지출 관리

회원가입과 로그인, 인증·인가를 통해 사용자별 데이터를 관리하는 기능을 구상하고 있다. 이후 알림 서비스가 추가될 가능성도 고려하되, 필요한 사용자 범위와 권한은 요구사항을 정리하면서 구체화할 예정이다.

지출 관리에서는 Google Sheets API를 활용해 스프레드시트의 지출 데이터를 가져오고 DB와 동기화하는 방안을 검토한다. 이를 바탕으로 카테고리별 소비, 월별 예산과 남은 생활비를 확인하는 것이 목표다. 동기화 주기나 수정 충돌을 어떻게 다룰지는 실제 데이터 사용 방식을 분석한 뒤 결정해야 한다.

### 채용공고와 일정 관리

채용공고를 등록하고 AI로 기업·직무와 요구 기술을 분석한 뒤, 결과와 지원 및 전형 진행 상태를 관리하는 기능을 구상하고 있다. 분석 결과는 저장해 다시 확인할 수 있도록 하되, AI가 제시한 정보는 원문과 대조할 수 있어야 한다.

일정 영역에서는 일간·주간·월간 계획과 체크리스트를 관리하려고 한다. 필수 목표와 추가 목표를 구분하고 완료 여부와 회고를 남기며, 자연어 요청으로 체크리스트를 현행화하는 방식도 검토할 예정이다.

### 기술 학습과 면접 준비

기술별 문제은행을 만들고, 직접 학습하고 검증한 정답을 저장해 복습에 활용하고 싶다. 등록한 문제를 바탕으로 AI와 질의응답을 진행하고, 답변 피드백과 면접 방식의 꼬리질문을 받아보는 방식이다.

답변 이력과 오답을 남기고 기술별 이해도를 살펴보는 기능도 구상 중이다. 어떤 기준으로 이해도를 표현할지는 실제 학습과 평가 방식부터 정리한 뒤 판단하겠다.

### 알림과 모바일 확장

일정, 채용공고 마감일, 예산, 복습 시점에 대한 통합 알림은 향후 확장 대상으로 두었다. 카카오 알림톡과 웹·모바일 푸시의 적용 가능성을 검토할 예정이다.

화면은 모바일에서도 사용할 수 있도록 반응형 웹을 고려하고, PWA와 Android 애플리케이션은 서비스 사용 경험과 필요성을 확인하며 검토한다.

## AI가 돕고 시스템이 관리할 것

AI는 채용공고를 분석하거나 학습 답변에 피드백을 제공하고, 자연어로 체크리스트를 정리하는 과정에서 활용하려고 한다. AI의 응답을 확인할 근거와 수정할 수 있는 방법을 함께 고민해야 한다.

**핵심 데이터와 업무 상태는 자체 시스템에서 관리**하는 방향이다. 예를 들어 AI가 할 일을 제안하더라도 실제 체크리스트의 내용과 완료 상태를 어떻게 저장하고 변경할지는 서비스가 책임져야 한다. AI가 생성한 코드 역시 직접 분석하고 설명할 수 있는 범위에서 적용할 계획이다.

## SI 프로젝트의 흐름을 개인 프로젝트에 적용하기

이번에는 바로 기능을 개발하기보다 프로젝트의 목적과 범위를 먼저 정리하려고 한다. 실생활에서 계속 사용할 서비스인 만큼, 무엇을 우선 만들고 어떤 기준으로 완료와 변경을 판단할지 살펴볼 필요가 있다.

프로젝트를 착수, 요구사항 분석, 시스템 설계, 개발·구현, 테스트·검증, 배포·전개, 운영·유지보수의 흐름으로 진행할 예정이다. 각 단계에서 필요한 산출물을 정하고 선택한 이유를 기록하면서 소프트웨어 개발 생명주기 전반을 경험하고자 한다.

착수 단계에서는 프로젝트 정의와 범위, 목표를 정리하고 개발 모델과 방법론, 단계별 산출물, WBS, 프로젝트 관리 기준을 검토할 계획이다. **개발 모델과 상세 기술 스택은 아직 확정하지 않았다.** 분석과 설계 과정에서 요구사항에 맞는 대안과 장단점을 비교한 뒤 선택하겠다.

## 문서도 프로젝트의 산출물로 관리한다

프로젝트 정의서와 요구사항 정의서, WBS, 설계서, 테이블 정의서와 API 명세, 테스트 시나리오와 결과, 기술 분석과 의사결정 기록(ADR), 트러블슈팅, 배포·운영 문서와 회고를 Markdown으로 관리할 예정이다. Git에 변경 이력을 남겨 결정이 바뀐 이유와 시점을 추적한다.

실행 가능한 소스코드, SQL과 테스트 코드는 각각의 원본 형식으로 관리한다. 이미지와 다이어그램은 설명이 필요한 곳에서 보조 자료로 활용할 계획이다. 문서의 양보다 현재 구현과 판단을 이해하고 다시 확인할 수 있는 내용이 중요하다.

## 앞으로의 기록

슬개리움의 개발 과정은 **사이드 프로젝트 > 슬개리움** 카테고리에 날짜순으로 기록할 예정이다. 착수부터 요구사항, 설계와 개발, 테스트와 운영까지 한 프로젝트가 변하는 과정을 이어서 남기고 싶다.

프로젝트 정의서와 개발 모델·방법론 선정은 다음 단계에서 별도로 진행한다. 이 글은 그 작업에 앞서 문제의식과 서비스 방향을 정리한 출발점이다. 기능 구현과 기술 학습을 구분하고, 필요한 기술의 내부 원리와 선택 이유를 확인하면서 과도한 설계보다 지속적인 개발과 개선을 우선하겠다.
