연구소에 할 일이 늘수록 처음 방문한 사람이 어디로 가야 할지 알기 어려워졌다. 설명창을 길게 열기보다 캐릭터 옆의 작은 로봇이 현재 방에서 할 일을 알려 주게 했다. PR #56의 `7b4c279`는 기능 실행 권한과 관계없는 로컬 튜토리얼 연출이다.

## 함께 움직이지만 서버에 공유하지 않는 상태

로봇은 내 화면에서만 보인다. 다른 참가자가 볼 필요가 없는 안내를 WebSocket으로 동기화하지 않았다. 서버와 DB를 바꾸지 않고 Scene이 생성·갱신·정리하는 객체로 둔다.

도입 커밋의 `frontend/src/game/pet/petTips.ts`는 로봇이 따라갈 자리를 계산한다.

```ts
export function petTarget(player: { x: number; y: number }, facingRight: boolean) {
  return { x: player.x + (facingRight ? -34 : 34), y: player.y - 10 }
}
```

처음에는 머리 높이여서 이름표와 겹쳤다. 어깨 높이와 뒤쪽으로 내리고 말풍선을 캐릭터 바깥으로 펼치게 수정했다. 대상을 더 눈에 띄게 만드는 것보다 기존 정보를 가리지 않는 것이 먼저였다.

## 매 프레임 같은 비율로 이동하면 속도가 달라진다

목표와 현재 위치 사이를 일정 비율로 줄이는 보간은 프레임 수에 영향을 받는다. 같은 파일은 시간에 따른 지수 감쇠를 사용한다.

```ts
export function follow(current: number, target: number, deltaMs: number, rate = 6) {
  return target + (current - target) * Math.exp(-rate * deltaMs / 1000)
}
```

목표가 고정된 조건에서 100ms 한 번과 10ms 열 번이 같은 결과가 되도록 검사했다. 실제로 목표가 이동하는 모든 상황이 완전히 같다는 뜻은 아니다. 프레임별 입력 표본은 달라질 수 있다. 위아래로 뜨는 연출과 눈 깜박임은 따라가기와 별도로 갱신한다.

## 아직 안 본 팁을 먼저 고르기

방별 팁을 RoomId의 Record로 두어 새 방을 추가할 때 목록도 점검하게 했다. 처음에는 그 방의 팁을, 다음에는 공통 팁을 보여 준다. 다 본 뒤에도 직전 문장을 즉시 반복하지 않는다.

같은 파일의 후보 선택 부분이다.

```ts
  const fresh = PET_TIPS[roomId].filter(tip => !seen.includes(tip))
  if (fresh.length) return pick(fresh)
  const common = COMMON_TIPS.filter(tip => !seen.includes(tip))
  if (common.length) return pick(common)
```

팁 데이터와 선택 규칙을 나누면 문구를 바꿀 때 Phaser 객체를 건드리지 않아도 된다. seen은 이 펫 객체의 기록이며 계정별 학습 진도를 저장하는 기능은 아니다.

PetBot은 방에 들어온 뒤 1.4초에 첫 팁, 이후 22~34초 간격으로 4.2초 동안 말한다. 클릭하면 바로 다음 팁을 보여 준다. 자동 설명을 기다리지 않아도 필요한 순간 다시 물어볼 수 있는 셈이다. 그림은 기존 픽셀 생성기에 기본·깜박임 텍스처를 추가했다.

## 상태와 화면을 나눠 확인하기

PR에는 프런트 테스트 126개, 타입 검사·빌드 통과가 기록돼 있다. 모든 방에 팁이 있고 길이 제한을 지키는지, 미노출 팁 우선과 직전 반복 방지, 시간 분할에 따른 따라가기 계산과 텍스처 등록을 검사했다.

당시 로컬 화면에서 첫 팁과 방별 문구를 확인하고 이름표 겹침을 수정했다고 남아 있다. 이번 작성에서는 코드를 대조했으며 작은 화면에서의 장시간 가림이나 운영 UX는 **확인하지 못함**이다.

## 배운 점

개인 안내는 공유 상태로 만들지 않아도 게임 안에 자연스럽게 놓을 수 있었다.
부드러운 따라가기는 프레임 수보다 경과 시간을 기준으로 설계해야 했다.
도움말도 정보의 양뿐 아니라 위치·주기·반복 순서를 함께 관리해야 했다.
