빈 방을 회원마다 자기 가구를 꾸미는 개인 기숙사로 바꾸었다. 폰에서 가구를 사고 방에 배치하는 흐름은 화면 연출과 함께 잔액, 소유권, 배치 가능 위치를 서버에서 관리해야 한다. 개발 로그와 PR #100·#101·#102, 로컬 코드를 대조했다.

## 스키마를 먼저 준비한다

V19는 가구 카탈로그와 회원별 보유 가구를 추가한다. 보관 중인지 배치 중인지와 좌표를 저장하고 배치 상태와 좌표의 관계를 DB 제약으로 묶는다. 구매 사유 공통코드도 먼저 준비했다. 기존 릴리스가 V18·V19를 지원하는 확장 단계와, V19를 요구하는 기능 릴리스를 분리한 이유다.

PR #102에는 운영 V19 적용을 마친 뒤 기능을 main에 반영했다고 기록돼 있다. #101은 main이 아닌 확장 브랜치로 병합됐기 때문에 같은 기능을 #102로 다시 올렸다. PR의 병합 표시만 보고 대상 브랜치를 확인하지 않으면 실제 main 반영 시점을 오해할 수 있었다.

## 잔액과 가구는 하나의 구매로 다룬다

서버는 카탈로그의 가격을 기준으로 잔액을 차감하고 보유 가구를 만든다. 구매 메서드는 트랜잭션으로 묶여 있으며 잔액이 부족하면 가구를 만들지 않는다. 회원별 가구 조회와 변경에는 회원 ID 조건을 붙여 다른 사람의 가구 ID로 배치하거나 보관하지 못하게 한다.

## 미리보기와 최종 판정을 분리한다

폰에서 배치를 선택하면 화면은 초록·빨강 미리보기로 가능한 위치를 보여 준다. 최종 요청에서는 서버가 벽, 문 앞과 기존 가구의 겹침을 다시 검사한다. 화면 표시만 신뢰하면 요청을 직접 바꿔 규칙을 우회할 수 있기 때문이다.

배치된 가구의 충돌 영역은 장면의 장애물 그룹에 추가하고, 보관하면 제거한다. 러그처럼 통과 가능한 가구는 충돌을 만들지 않는다. 화면에 그려진 물체와 실제 이동 판정이 같은 상태를 따라야 한다.

## 확인한 범위

PR 기록에는 구매·잔액 부족·배치·타인 가구 차단 서비스 테스트, 비회원 401 계약 테스트, 프런트 테스트 151개와 타입 검사·빌드 통과가 남아 있다. 로컬 브라우저는 API 응답을 대체해 배치와 충돌·보관을 확인했다. 실제 로그인 회원 화면은 당시 확인하지 못했다고 기록돼 있으며, 이 글 작성 과정에서 운영 기능을 재검증하지 않았다.
