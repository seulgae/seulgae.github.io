방이 늘어나면서 어디에서 무엇을 할 수 있는지 찾기 어려워졌다. 동시에 커피로 회복하고 활동으로 감소하는 자원을 피로도라고 부르니 값의 방향도 직관적이지 않았다. PR #103은 폰 지도와 용어를 함께 다뤘다.

## 지도 배치를 방 데이터에서 계산한다

여러 문이 있는 방을 구역 중심으로 삼고, 각 문의 목적지를 주변 칸으로 배치한다. `mapLayout.ts`는 문 좌표를 좌우·상하 위치로 변환하고 다른 중심 방으로 이어지는 문은 구역 전환으로 표현한다. 현재 방에 표시를 붙이고 각 방에서 할 일을 볼 수 있다.

지도를 별도 그림으로 고정하는 대신 기존 방 연결 데이터에서 계산한 선택이다. 다만 좌표를 몇 개의 칸으로 분류하는 규칙이므로, 새로운 배치에서 칸이 겹치거나 분류가 맞지 않는 경우까지 자동으로 해결한다고 단정할 수 없다. 방을 바꿀 때 지도 결과도 확인해야 한다.

## 사용자에게 보이는 의미를 맞춘다

활동할 때 줄고 커피로 회복되는 값의 화면 이름을 피로도에서 스태미나로 바꿨다. 저장된 DB 컬럼과 API 필드 `fatigue`는 유지했다. 화면 용어와 기존 데이터 계약을 분리해 스키마 변경 없이 혼동을 줄인 것이다.

오락실에는 대화와 혼잣말을 하는 단골 NPC도 추가했다. 개발 로그에는 프런트 테스트 152개와 타입 검사, 로컬 화면에서 지도와 NPC 확인이 기록돼 있다. 이번 글 작성 시 해당 프로젝트의 테스트를 다시 실행한 결과는 아니다.
