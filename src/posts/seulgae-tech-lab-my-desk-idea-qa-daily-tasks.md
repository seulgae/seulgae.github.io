서비스 연구실의 업무 게시판 흐름을 아이디어 기획, QA와 내 자리 컴퓨터로 바꾸었다. PR #108·#109는 데이터 구조를 먼저 확장하고 새 화면을 사용하는 단계로 나눴다.

## 기존 QA를 옮기고 새 업무를 나눈다

V21은 아이디어 글과 QA 티켓을 각각 저장한다. 기존 QA 티켓을 같은 ID로 옮기고 상태를 새 흐름에 맞게 변환했다. 과거 유지보수·운영 기록과 기존 테이블은 이후 축소 단계에서 다룰 계획이다. V21 적용 후 들어온 기존 QA 티켓을 다시 이관하는 일도 남은 작업으로 기록됐다.

QA 상태는 등록에서 조치 중, 조치 완료 순으로 진행한다. 저장소는 현재 상태가 예상한 값과 같을 때만 갱신한다. 두 요청이 같은 상태에서 동시에 처리하려 할 때 조건부 갱신이 중복 전이를 막는 방식이다.

## 오늘 업무는 기존 기록에서 계산한다

내 자리의 메일 화면은 낚시와 오락, 커피, 게시판, Java 연습을 오늘 수행했는지 보여 준다. 별도 업무 완료 테이블을 만들지 않고 기존 동전 사유별 기록과 잡은 물고기를 바탕으로 계산한다. 기록을 재사용하면 기기별 화면 상태 대신 서버 자료를 기준으로 확인할 수 있다. 일일 보상 제한의 동시 요청 보장 범위는 별도 검증이 필요하다.

Java 연습은 사용자가 프로그램 전체를 제출하는 방식이 아니다. 형식 문자열을 받아 고정된 인자와 `String.format`으로 결과를 비교하고, 과도한 폭·정밀도 입력은 제한한다. 화면에 보이는 학습 경험과 서버가 허용하는 입력 범위를 나눴다.

PR에는 새 서비스·API 계약 테스트와 프런트 159개 테스트, 타입 검사 통과가 기록돼 있다. 로컬 브라우저 확인에는 로그인과 API 대체 응답을 사용했으며 실제 로그인 상태는 당시 확인하지 못했다.
